# Social Fetch — AI agent and crawler access file
# Last updated: 2026-09-08

## What Social Fetch is
Social Fetch is a hosted social media scraper API over synchronous REST: structured public social and web data as JSON.
One API key (x-api-key: sfk_...), one { data, meta } response envelope, 206 documented operations. Strong coverage for Reddit, TikTok, and Instagram, plus X/Twitter, YouTube, Facebook, LinkedIn, Threads, Telegram, GitHub, Spotify, Rumble, and general web pages.
Hosted MCP: https://api.socialfetch.dev/mcp (OAuth by default, or x-api-key if the client never prompts). TypeScript SDK: @socialfetch/sdk.
Docs: https://www.socialfetch.dev/docs · Pricing: https://www.socialfetch.dev/pricing · Credits: https://www.socialfetch.dev/docs/credits.mdx
Platform hubs: https://www.socialfetch.dev/platforms (Reddit: https://www.socialfetch.dev/platforms/reddit).

## Key capabilities for agents
- Fetch profiles, posts, comments, transcripts, search, commerce, ads, and web extraction as JSON (no DIY scraper fleet)
- Unified envelope and consistent field naming across platforms (no HTML parsing)
- Explicit lookupStatus on many routes so HTTP 200 does not imply found
- Cursor pagination via data.page.nextCursor / data.page.hasMore and query cursor
- Hosted MCP at https://api.socialfetch.dev/mcp for Cursor, Claude, VS Code, and other MCP clients — OAuth, or x-api-key from an env var if the client never prompts
- Agent Skills: `npx skills add social-freak-ltd/socialfetch -s socialfetch` — https://www.socialfetch.dev/docs/integrations/skills.mdx
- 100 free credits on signup; whoami and balance are free

## Instructions

- Authenticate every /v1/** request with the x-api-key header. Never put the key in the URL or query string.
- Never invent endpoint paths. Start with https://www.socialfetch.dev/llms.txt, pick a platform file under /llms-{platform}.txt, or use https://www.socialfetch.dev/llms-endpoints.txt for the full list with markdown doc links.
- Prefer the linked per-route .mdx docs page (or Accept: text/markdown on /docs/**) over parsing OpenAPI for routine integration work.
- Published blog posts also have markdown twins: append .mdx to /blog/{slug} (or Accept: text/markdown on the HTML URL).
- Paginate list routes the same way: read data.page.nextCursor, send it back as the cursor query parameter, stop when data.page.hasMore is false. Never build or decode a cursor yourself.
- On HTTP 200, inspect lookupStatus (found / not_found / private / …) when present before treating the payload as a successful find.
- On non-200 responses, parse the shared { error } envelope and keep requestId from meta for support. See errors docs.
- Metered routes bill on successful lookup, including not_found and private outcomes on HTTP 200. Plan batch jobs against the credits guide.
- For AI IDE tool calling, prefer MCP (OAuth, or x-api-key if the client never prompts). For server-side pipelines, prefer @socialfetch/sdk or REST with an API key.

## Authentication
REST / SDK: x-api-key header required on /v1/** unless the operation is anonymous.
MCP (https://api.socialfetch.dev/mcp): OAuth in the browser by default. If the client never prompts, send the same x-api-key header. Do not put the key in the URL or in Authorization.
Create a key: https://app.socialfetch.dev/api-keys (100 free credits on signup).
